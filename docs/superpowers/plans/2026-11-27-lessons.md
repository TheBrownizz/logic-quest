# Interactive Lessons Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add Brilliant-style interactive lessons (engine + 9 widgets + 15 lessons for Switching stages 1–5) before each stage's rooms.

**Architecture:** A lesson is content data: an ordered list of typed steps (`explain`, `widget`, `check`, `try`, `recap`) plus a skip-quiz pool. A generic LessonScreen renders steps. Widgets live in a registry keyed by name. Each widget exports a component and a pure `isGoalMet(state, goal)` that the validator also uses. Task 1 builds the engine and ships stub files for every widget and every stage's lessons. Tasks 2–6 then fill disjoint files in parallel git worktrees.

**Tech Stack:** Existing: Vite 5, React 18, TS strict, Vitest, Playwright, CSS/SVG. No new dependencies.

**Spec:** `docs/superpowers/specs/2026-11-27-lessons-design.md` (Hebrew). Section 6.10 holds the binding decisions.

## Global Constraints

- Hebrew UI with RTL. Formulas, bit strings and expressions inside Hebrew text go in `ltr()` isolates. The existing content lint (`tests/content/switching.test.ts`) must also run over all lesson strings.
- No new npm dependencies and no runtime network calls. Respect `prefers-reduced-motion`: show the final state and skip the animation. Use theme tokens only.
- Every widget is operable by keyboard. Lesson screens work at 400px width. Embedded `try` labs may require desktop width.
- `explain` text is at most about 60 words. A lesson never has more than 2 consecutive `explain` steps.
- Every `check` has exactly one correct answer and a feedback string for EVERY wrong option.
- Skip quiz: a pool of at least 6 check-format questions, 4 drawn; it fails on the first wrong answer. After a failure, retry is allowed after 10 minutes or after finishing the lesson.
- Lesson done = reached the end OR passed the skip quiz. A stage's rooms and run unlock when all of its lessons are done OR at least one of its rooms is already solved. Unlock is permanent. The 60% stage-to-stage rule is unchanged.
- `try` steps reuse `LabPuzzle` types and checkers. They have no stars, write no `helped` and keep no drafts.
- Save: `SaveData.lessons: Record<lessonId, { stepId: string; done: boolean; skipped?: boolean; quizFailedAt?: number }>`, optional, default `{}`, `version` stays 1, and bad entries are dropped. An unknown `stepId` resumes at the start.
- Routes: `#/lesson/:lessonId` and `#/lesson/:lessonId/:stepId`. "Back" goes to the lesson's stage screen.
- IEEE-754 is single precision only (bias 127), with normal numbers as goals.
- Content is original wording, factually verified, and sourced as `"סילבוס: <topic>"`.

## Review Focus

1. **A saved `stepId` that was removed from the lesson:** resume at step 1 and don't crash. Test in Task 1.
2. **A v1 save with solved rooms and no `lessons` field:** those stages stay open. Test in Task 1.
3. **Double-clicking "המשך" or answering a check twice:** advance exactly one step. Test in Task 1.
4. **A widget goal that is unreachable because of a content typo:** the validator must catch it through `isGoalMet(exampleState, goal)`. Test in Tasks 1–6.
5. **The skip quiz cooldown across a reload:** it is persisted through `quizFailedAt`. Test in Task 1.

### Task 1: Lesson engine (sequential; everything else depends on it)

**Files:** everything above except the real widget implementations and real lesson content. Modify `src/game/progress.ts` (the `lessons` field), `src/ui/router.ts`, `src/ui/App.tsx`, `src/ui/StageScreen.tsx` (the "למד" section and gating), `src/ui/lab/*` (extract embeddable lab components for `try`), and `README.md` (lesson authoring conventions).

**Interfaces (produced, exact):**
```ts
type WidgetName = 'BaseDial'|'BaseConvert'|'ComplementLab'|'BitField'|'GateToy'|'IdentityBench'|'TruthToMap'|'RippleTimeline'|'MuxToy'
type Step =
  | { id: string; kind: 'explain'; text: string; figure?: string /* inline SVG markup id from a figures map, optional */ }
  | { id: string; kind: 'widget'; prompt: string; widget: WidgetName; config: unknown; goal?: unknown; example?: unknown /* a state that meets goal; required when goal is set */ }
  | { id: string; kind: 'check'; prompt: string; options: string[]; correct: number; feedback: string[] /* same length; feedback[correct] = praise/explanation */ }
  | { id: string; kind: 'check-number'; prompt: string; answer: string; compute: () => string; feedbackWrong: string }
  | { id: string; kind: 'try'; prompt: string; puzzle: LabPuzzle; hints: Hint[] }
  | { id: string; kind: 'recap'; points: string[] }
interface SkipQuestion { id: string; prompt: string; options: string[]; correct: number }
interface Lesson { id: string; stage: string; order: number; title: string; minutes: number; blurb: string; steps: Step[]; skipQuiz: SkipQuestion[]; source: string }
interface WidgetDef<C, S, G> { Component: React.FC<{ config: C; goal?: G; onState: (s: S) => void; reducedMotion: boolean }>; initial: (c: C) => S; isGoalMet: (s: S, g: G, c: C) => boolean }
// registry: Record<WidgetName, WidgetDef<any, any, any>>
validateLessons(world: World, lessons: Lesson[]): string[]
lessonsForStage(stageId: string): Lesson[]
lessonDone(save: SaveData, lessonId: string): boolean
stageRoomsOpen(world: World, stageId: string, save: SaveData): boolean
drawQuiz(pool: SkipQuestion[], rng: () => number): SkipQuestion[]   // 4 distinct
quizCooldownLeft(save: SaveData, lessonId: string, now: number): number // ms, 0 = allowed
```
- **Stubs:** every widget file exports a placeholder Component ("וידג'ט בבנייה"), and `isGoalMet` returns true. Every stage lessons file exports `[]`, except stage1.ts, which holds ONE complete sample lesson that uses explain, check, check-number, try (number), recap and a widget step with no goal (so it works on the stub).
- **Validator checks:**
  - unique ids;
  - `stage` exists;
  - steps are non-empty and no more than 2 `explain` in a row;
  - check `feedback.length === options.length`, with `correct` in range;
  - check-number `compute() === answer` after normalising;
  - a `try` puzzle passes the same validation as a room (reuse `validateWorld` internals);
  - a widget with `goal` has `example`, and `registry[w].isGoalMet(example, goal, config)` holds;
  - `skipQuiz.length >= 6` with distinct options;
  - `source` is non-empty;
  - the existing text lint applies to every string.
- **Tests:** unit tests for everything listed above, including Review Focus 1, 2, 3 and 5. e2e covers:
  - the sample lesson from start to finish, after which the rooms unlock;
  - reload mid-lesson, resuming at the same step;
  - skip quiz pass and fail, with the cooldown message;
  - the lesson at 400px with no horizontal scroll.

- [ ] Write failing tests (unit + e2e) → implement → `npm test && npm run build && npm run e2e` green → commit `feat: lesson engine`.

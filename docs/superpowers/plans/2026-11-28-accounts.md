# Accounts & Cloud Save Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Google sign-in via Supabase and cloud sync of `SaveData`. The game stays local-first and fully playable as a guest.

**Architecture:**
- The local store stays the source of truth, under per-owner localStorage keys.
- A pure `mergeSaves` combines saves monotonically.
- A `SyncEngine` pulls on sign-in, on load and on tab focus. It pushes with a debounce, using compare-and-set on a `rev` column.
- Auth uses PKCE so it doesn't clash with hash routing.
- Without Supabase env vars, all account UI is hidden.

**Tech Stack:** existing (Vite 5, React 18, TS strict, Vitest, Playwright) plus `@supabase/supabase-js@2.45.4` (exact version).

**Spec:** `docs/superpowers/specs/2026-11-28-accounts-design.md` (Hebrew; 5.7 binding)

## Global Constraints
- The game must work with no env vars, no network and no sign-in. In that case it behaves exactly like today.
- Never embed a service key in client code. The anon key and URL come only from `import.meta.env.VITE_SUPABASE_URL` / `VITE_SUPABASE_ANON_KEY`.
- `mergeSaves` never loses progress. It is commutative where the rules are symmetric, and idempotent: `merge(a, a) == a`.
- Local keys:
  - guest: `logic-quest-save`
  - user: `logic-quest-save:<userId>`
  - UI-only state lives under separate `lq-ui:*` keys.
- Never merge a guest save into an account without the explicit "צרף" choice.
- Unit tests and e2e must not touch the network. Use a fake Supabase client, injected via `window.__LQ_FAKE_SUPABASE__` only when `import.meta.env.MODE === 'test'` or `VITE_E2E_FAKE=1`.
- Hebrew UI, theme tokens only, keyboard accessible.

## Review Focus
1. Two devices push concurrently. CAS retry plus merge must keep both devices' solved rooms (unit test with the fake).
2. User A signs out and user B signs in on the same browser. B never sees A's data, and A's save survives (e2e).
3. Offline or Supabase errors: the game keeps working, shows the ⚠ indicator, and retries later (unit test).
4. The OAuth return with `?code=` plus a previous hash: the hash is restored and the query removed (unit test of the redirect helper).
5. A new SaveData field without a merge rule fails a test.

### Task 1: mergeSaves, savedAt and per-owner local stores
- **Produces:**
  - `mergeSaves(local: SaveData, remote: SaveData): SaveData`, following spec 5.3 plus 5.7.1 exactly;
  - `MERGE_RULES: Record<keyof SaveData, string>`, with a test asserting the keys equal `Object.keys(emptySave())`;
  - `SaveData.savedAt: number`, optional and defaulting to 0, set on every `save()`;
  - `new LocalProgressStore({ key?: string, storage?: Storage })`, keeping today's default key.
- **Tests:** every field rule, idempotency, never-lose properties (randomised with a seeded generator), and Review Focus 5.
- [ ] RED → GREEN → `npm test && npm run build` → commit `feat: save merging and per-owner local stores`

### Task 2: Cloud client and SyncEngine
- **Produces:**
  - `SupabaseLike`;
  - `getSupabase()`, which returns null when the env is missing;
  - `class SyncEngine { constructor(client, userId, local: ProgressStore, apply: (fn) => void); start(): void; stop(): void; notifyChanged(d: SaveData): void; status: 'synced'|'saving'|'offline'; onStatus(cb) }`.
- **Behaviour:**
  - pull runs on start and on `visibilitychange`;
  - pull merges and then calls `apply` with the merged result;
  - push is debounced 2 s and does `update ... where rev = known`;
  - when 0 rows are updated: pull, merge, retry, up to 3 times;
  - the first row is created with insert on conflict do nothing, then re-pull;
  - on error: status `offline`, retry with backoff (5 s, 15 s, 60 s).
- **Fake client:** `tests/cloud/fakeSupabase.ts`, an in-memory table that supports `rev` and lets tests simulate a concurrent writer.
- **Tests:** Review Focus 1 and 3.
- [ ] RED → GREEN → commit `feat: cloud sync engine`

### Task 3: Auth flow and account UI
- **Produces:**
  - `signInWithGoogle()`: stores the current hash in sessionStorage `lq-ui:return-hash`, then calls `auth.signInWithOAuth({ provider: 'google', options: { redirectTo: location.origin + location.pathname, flowType: 'pkce' }})`.
  - `handleRedirect()`: if `?code=` is present, exchanges it for a session, `history.replaceState`s away the query, and restores the hash.
  - `signOut()` and `deleteAccount()`. `deleteAccount` invokes the edge function, then clears `logic-quest-save:<uid>`.
- **SaveProvider integration:**
  - When signed in, use the user's local key and run the SyncEngine.
  - On the first sign-in with guest progress, show AttachGuestDialog ("לצרף את ההתקדמות מהמכשיר הזה לחשבון?" with the buttons "צרף" / "השאר כאורח").
  - On sign-out, return to the guest key.
- **UI:**
  - the header shows AccountButton ("התחברות עם Google"), or an avatar plus menu (התנתקות, מחיקת חשבון, פרטיות) and the SyncBadge (✓ / ⟳ / ⚠);
  - GuestNudge appears once, after 3 solved rooms, and is dismissible;
  - DeleteAccountDialog requires typing "מחק";
  - PrivacyPage.
  - All account UI is hidden when `getSupabase()` is null.
- **Tests:** a unit test for the redirect helper (Review Focus 4). e2e with the fake client covers guest mode, simulated sign-in, attach and keep-guest, sign-out and switching user (Review Focus 2), and deleting the account.
- [ ] RED → GREEN → `npm test && npm run build && E2E_PORT=4201 npm run e2e` → commit `feat: Google sign-in and account UI`

### Task 4: Backend files, setup guide and CI env
- `supabase/schema.sql`: the table from spec 5.1 plus `rev int not null default 0` and RLS.
- `supabase/functions/delete-account/index.ts` (Deno): verifies the caller's JWT, then deletes `auth.admin.deleteUser(uid)` with the service role key from the function's env.
- `docs/SETUP-ACCOUNTS.md`: a Hebrew guide with numbered steps, assuming a beginner, covering:
  - creating the Supabase project;
  - running schema.sql;
  - creating the Google Cloud OAuth client, with origins and redirect URIs;
  - enabling the Google provider in Supabase;
  - setting the Site URL and redirect URLs (`https://thebrownizz.github.io/logic-quest/`, `http://localhost:5173/`);
  - deploying the function (CLI commands);
  - setting GitHub repository variables `VITE_SUPABASE_URL` and `VITE_SUPABASE_ANON_KEY`.
- deploy.yml passes those variables to the build step.
- vite.config: server port 5173 strictPort.
